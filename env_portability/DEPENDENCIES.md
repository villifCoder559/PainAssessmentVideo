## Manifest-only declarations and exclusions

The complete prior manifest/configuration audit was stored in
`env_reproducibility/locks/dependency-audit.json`, which is now removed. It is available with
`git show ee49793:env_reproducibility/locks/dependency-audit.json`. Python/requirements files in
MAE_DFER, VideoMAEv2, JEPA, V-JEPA 2, and making_better_mistakes were inspected.
The current Python sources match that audit byte-for-byte; the environment verifier
is additionally scanned in the fresh audit.

The CUDA profile supplies torch/torchvision through official CUDA 11.8 wheels.
It supplies timm, torchmetrics, torch-optimizer, and WebDataset through pip to keep one PyTorch
provider. All remaining common dependency requirements have the same providers and
constraints as the CPU file. Native torchsort remains a separate matching wheel or
source-build step; do not install the Conda CPU extension into the GPU profile.

- Torchaudio: declared by VideoMAEv2, but never imported by live repository code; optional matched audio stack only.
- wandb, beartype, braceexpand, iopath, peft, fire, python-box, ftfy: upstream declarations without live imports; install only for a separate upstream workflow that actually needs them.
- tensorflow, fastText, git-lfs, old triton pins: historical setup declarations; no live Python imports requiring them. Git LFS is only needed if separately fetching LFS-hosted assets.
- huggingface_hub, tokenizers, protobuf, JAX, BLAS, codecs, OpenMP and other native libraries: package-managed transitives; not duplicated as direct project requirements.
- dlib, face_alignment, current driver, compiler metapackages, old cudatoolkit and other installed-only packages: excluded from the common environment.
